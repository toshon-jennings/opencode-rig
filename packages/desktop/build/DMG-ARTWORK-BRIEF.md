# OpenCode Rig — DMG background

`background.png`, 540×380, generated by `make-background.py`. House convention:
`~/.config/agent-rules/DMG.md`.

Brand is pulled from `assets/logo-rig-dark.svg` and `assets/og-image.html` — the
"opencode" wordmark is those exact paths, and RIG is traced off `assets/og-image.png`
onto the same 6-unit grid. Nothing here is invented.

```bash
python3 packages/desktop/build/make-background.py
```

---

## The concept

**The prompt is the arrow.**

A standard DMG puts a chevron between the app icon and the Applications folder. This
one is a terminal, so the chevron is a real `❯` — followed by a block cursor stepping
right toward `/Applications`, fading as it goes. The install gesture and the shell
prompt are the same mark.

The pale band the icons sit on is a **selected line**: a terminal inverts selection to
light-on-dark, which is exactly the mid-luminance strip Finder's labels need. The band's
edges dissolve into 6px blocks — the same unit the letterforms are built from — and the
grid continues through it, inverted, so it reads as the same surface rather than a panel
laid over one.

## Layout — 540×380, origin top-left

Icons are fixed by house convention at **(140, 225)** and **(400, 225)**, 100px.

| Band      | y           | Treatment                                                                  |
| --------- | ----------- | -------------------------------------------------------------------------- |
| Field     | 0–142       | Dark. Wordmark, then three dim lines of syntax-coloured blocks             |
| **Plate** | **142–322** | **Silver. Solid core 160–304, dithered edges. Non-negotiable — see below** |
| Floor     | 322–380     | Dark. The accent rule from the og-image, and nothing else                  |

Free horizontal space between the icon boxes is **x = 190–350**. The `❯` sits at
208–244 and the cursor trail ends at 334, clear of both.

### Why the plate is non-negotiable

Finder draws icon filename labels in the **system** label colour: white in Dark Mode,
near-black in Light Mode. You cannot override it from the artwork. So wherever labels
land has to be mid-luminance — light enough for black text, dark enough for white.

Measured on the shipped PNG at the label row (y=285):

|                      | luminance |
| -------------------- | --------- |
| app icon, x=140      | **0.61**  |
| /Applications, x=400 | **0.63**  |

Target is 0.60–0.75. Re-check after any edit:

```bash
python3 -c "from PIL import Image; im=Image.open('packages/desktop/build/background.png').convert('RGB'); print([round(sum((0.299*r+0.587*g+0.114*b)/255 for r,g,b in im.crop((cx-50,277,cx+50,293)).getdata())/1600,3) for cx in (140,400)])"
```

The plate also feathers off the left and right frame edges. It is fully opaque from
x=46 to x=494, which covers both icon boxes (90–190 and 350–450) with room to spare.

## Palette

Sampled from `assets/og-image.html`. Do not introduce colours outside this set.

| Role                             | Hex                                     |
| -------------------------------- | --------------------------------------- |
| Field, top → bottom              | `#1D1A19` → `#121010`                   |
| Plate, top → bottom              | `#C4BDBA` → `#9C9592`                   |
| Wordmark silver / white / shadow | `#B7B1B1` / `#F1ECEC` / `#4B4646`       |
| RIG + cursor amber               | `#FAB283`                               |
| Chevron ink                      | `#5E3A21`                               |
| Accents (code lines, rule)       | `#7FD88F` `#56B6C2` `#9D7CD8` `#FAB283` |

The chevron is **dark** amber, not `#FAB283`. On a 0.65-luminance plate the brand amber
sits at 0.76 and vanishes; it only reads as light-on-dark. Amber stays in the dark bands.

## Why there is no retina asset in the build

`make-background.py` also writes `retina-src/background@2x.png`. Nothing consumes it — it is
gitignored and regenerated on demand — but note it lands in a subdirectory, deliberately
**outside** `buildResources`, and it must stay there.
If electron-builder finds `background.png` and `background@2x.png` together it runs
`tiffutil` itself and ships the TIFF — even when `dmg.background` explicitly names the
PNG — and macOS 26 Finder renders multi-representation TIFFs as a plain grey window with
no error. `electron-builder.config.test.ts` guards this.

Cost, stated honestly: the background is soft on a retina display. Every shipping app
with a DMG background eats this. Revisit if a future macOS renders the TIFF pair.

## Apple Silicon — the build tool ships a broken background

On arm64 `hdiutil` cannot create HFS+, so electron-builder falls back to APFS and writes
a classic HFS-style alias into `.DS_Store`. Those identifiers don't resolve on an APFS
volume, so **Finder silently falls back to grey**. Nothing errors; `.DS_Store` inspects
as perfect.

`build/fix-dmg-background.sh` re-drives Finder over the real volume so it writes a valid
alias, then repacks. `bun run package:mac` runs it over every DMG in `dist/`.

Tell a good alias from a generated one by size — electron-builder writes ~408 bytes,
Finder ~658.

The release workflow runs the repair while the GitHub release is still a draft, then
regenerates the DMG blockmap and the DMG entry in `latest-mac.yml` before replacing all
three uploaded assets. If Finder automation or metadata refresh fails, the desktop job
fails and the incomplete release remains unpublished.
